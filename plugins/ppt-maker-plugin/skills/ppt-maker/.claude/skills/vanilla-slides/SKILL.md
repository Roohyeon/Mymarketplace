# Vanilla Slides

외부 라이브러리·빌드 도구 없이, 브라우저에서 바로 여는 **HTML 파일 하나**로 발표 자료를 만든다.

## 기본 지원 기능 (템플릿에 구현됨)

| 기능 | 동작 |
|---|---|
| 슬라이드 이동 | `→` `↓` `PageDown` 다음 · `←` `↑` `PageUp` 이전 · `Home` / `End` 처음 / 끝 (발표용 클리커는 PageUp/PageDown을 보냄) |
| 전체 화면 | `F` 토글 (`Esc`로도 해제 — 브라우저 기본 동작) |
| 슬라이드 번호 | 캔버스 오른쪽 아래 `3 / 12` 표시, `aria-live`로 스크린리더에 안내 |
| 화면 맞춤 | 1920×1080 고정 캔버스를 창 크기에 맞춰 `scale` — 어떤 화면에서도 레이아웃 동일 |
| URL 해시 | `#3` = 3번째 슬라이드. 새로고침해도 같은 위치, 링크 공유 가능 |

## 작업 순서

1. **내용 파악** — 발표 주제, 청중, 대략의 슬라이드 수를 확인한다. 사용자가 원고·개요를 줬다면 그것을 따른다. 정보가 부족하면 합리적으로 구성하고 진행한다 (질문은 꼭 필요할 때만).
2. **템플릿 복사** — [`assets/template.html`](assets/template.html)을 읽어 사용자가 지정한 위치(지정이 없으면 작업 디렉터리의 `<주제>.html`)에 새 파일로 만든다.
3. **치환** — `{{TITLE}}`, `{{EYEBROW}}`, `{{SUBTITLE}}`을 채운다. `<title>`과 `.deck`의 `aria-label`에도 `{{TITLE}}`이 있다.
4. **슬라이드 작성** — `<!-- ===== SLIDES START ===== -->`와 `END` 사이의 예시 슬라이드를 실제 내용으로 교체한다. 아래 "슬라이드 작성 규칙"을 따른다.
5. **테마 조정 (선택)** — 사용자가 색·분위기를 요청하면 `:root` 토큰만 바꾼다. 개별 요소에 색을 하드코딩하지 않는다.
6. **검증** — 아래 체크리스트를 확인하고, 가능하면 브라우저로 열어 확인하라고 안내한다.

## 슬라이드 작성 규칙

- 슬라이드 하나 = `<section class="slide">` 하나. `.deck`의 **직계 자식**이어야 번호에 포함된다.
- `.counter` 요소와 `<script>`는 지우거나 옮기지 않는다.
- 캔버스는 **1920×1080 px 고정**이므로 크기는 px로 쓴다. 본문 기본 40px, 최소 28px 미만으로 내리지 않는다.
- 슬라이드당 핵심 메시지 하나, 글머리표 3–5개, 한 줄 30자 안팎. 넘치면 슬라이드를 나눈다 (캔버스는 `overflow: hidden`이라 넘친 내용은 잘린다).
- 발표자 메모는 `<aside class="notes">…</aside>`에 넣는다 (화면에 표시되지 않음).

제공되는 클래스:

| 클래스 | 용도 |
|---|---|
| `.slide--title` | 표지 (큰 제목, 왼쪽 정렬) |
| `.slide--center` | 가운데 정렬 (섹션 구분, 마무리) |
| `.eyebrow` | 제목 위 작은 강조 라벨 |
| `.lead` | 부제·요약 문단 |
| `.muted` | 보조 텍스트 색 |
| `.cols` / `.cols.cols--3` | 2단 / 3단 그리드 |
| `.card` | 테두리 있는 상자 (`.cols` 안에서 비교·나열용) |

필요한 레이아웃이 없으면 `<style>`의 "Slide content" 구역에 클래스를 추가한다. 인라인 `style`은 한두 곳의 미세 조정에만 쓴다.

예시:

```html
<section class="slide">
  <p class="eyebrow">비교</p>
  <h2>두 가지 접근</h2>
  <div class="cols">
    <div class="card"><h3>A안</h3><p>빠르게 시작할 수 있다</p></div>
    <div class="card"><h3>B안</h3><p>장기 유지보수에 유리하다</p></div>
  </div>
  <aside class="notes">A안은 일정이 급할 때만 권장한다고 말할 것.</aside>
</section>
```

## 반드시 지킬 것

- **외부 의존성 금지** — CDN 스크립트·프레임워크·빌드 도구를 쓰지 않는다. 글꼴도 시스템 글꼴 스택을 쓴다 (오프라인 발표장에서도 동작해야 함). 사용자가 웹 글꼴을 명시적으로 원할 때만 Google Fonts `<link>`를 추가하고, 폴백을 남긴다.
- **비활성 슬라이드에 `display: none` 금지** — `visibility: hidden` + `inert`를 쓴다 (전환 애니메이션과 접근성 유지). 템플릿의 `goTo()`가 처리한다.
- **상태 변경은 `goTo()` 한 곳에서만** — 새 입력(클릭, 스와이프 등)을 추가할 때도 `next()/prev()/goTo()`를 호출하게 만든다.
- 키보드 처리 규칙 유지: 입력창 포커스·Ctrl/Alt/Meta/Shift 조합·`e.repeat`는 무시하고, **처리한 키에만** `preventDefault()`.
- 애니메이션은 `opacity`와 `transform`만 쓰고, `prefers-reduced-motion`을 존중한다.

## 검증 체크리스트

- [ ] `{{…}}` 자리표시자가 남아 있지 않다 (`Grep`으로 `\{\{` 검색)
- [ ] 모든 슬라이드가 `.deck`의 직계 자식 `section.slide`이다
- [ ] 글자가 1920×1080 캔버스 밖으로 넘치지 않을 분량이다
- [ ] `<script>`·`.counter`가 그대로 있다
- [ ] 외부 `<script src>`가 없다

사용자에게 안내할 사용법: 파일을 브라우저로 열고 `F`로 전체 화면, 방향키로 이동. 특정 슬라이드는 주소 끝에 `#5`처럼 붙여 바로 연다.

## 확장 요청이 올 때

사용자가 추가 기능을 원하면 기존 구조(`goTo` 단일 진입점)를 유지한 채 덧붙인다. 프로젝트에 `research/vanilla-slides-research.md`(설계 근거)와 `examples/vanilla-deck.html`(전체 기능 구현 예)이 있으면 먼저 참고한다.

- **슬라이드 전환 효과(slide/zoom)** — Web Animations API(`el.animate`)로 나가는/들어오는 슬라이드를 동시에 애니메이션, 전환 중 입력은 1개만 버퍼
- **빌드 효과(요소 순차 등장)** — `.step` + `data-step` 그룹, `.is-visible` 클래스 토글
- **발표자 노트/보기** — `N`으로 노트 오버레이, `S`로 `?presenter` 창 + `BroadcastChannel` 동기화
- **터치·클릭 이동** — Pointer Events 스와이프, 화면 왼쪽 30% 클릭 = 이전
- **진행 바** — `transform: scaleX(var(--progress))`
- **인쇄/PDF** — `@media print`에서 모든 슬라이드를 `visibility: visible`, `break-after: page`
